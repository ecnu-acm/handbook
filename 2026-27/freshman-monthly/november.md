## 学术诚信

无论是算法竞赛还是今后的学术道路或者职业道路，学术诚信都是重中之重，视其为一切成果之根本。

以下文字引自 [《萌新认识与入门算法竞赛》](https://github.com/NullResot/XCPC-Beginner-Guide)，其中的观点深以为然，与大家共勉：
> 在算法竞赛的求索之路上，我们追求卓越的代码与精妙的算法，这固然重要。然而，超越所有荣誉与排名的，是对**学术诚信**的坚定秉持。每一次代码的提交，都应是独立思考的结晶，真实反映自身能力的提升。作弊行为不仅损害了竞赛的公平基石，更是对个人学习机会的自我剥夺。维护这一原则，方能赢得社区的尊重，并为未来的学术与职业生涯奠定坚实基础。

## 比赛简介

ACM 新生月赛是面向大一新生举办的程序设计竞赛，旨在帮助同学们：

* 检验近期算法与程序设计知识的学习成果。
* 熟悉 XCPC 竞赛形式和在线评测系统（OJ）。
* 培养独立分析问题、设计算法和编写代码的能力。
* 提供一个交流学习以及动手的平台。

无论你是第一次参加程序设计竞赛，还是已经有了一定的算法基础，都欢迎积极参与、挑战自我。

## 赛制与基本信息

* **参赛对象**：大一新生
* **比赛形式**：个人赛
* **比赛平台**：[VOJ](https://voj.mobi/)
* **比赛时间**：11月22日 14:00-17:00
* **比赛地点**：理科大楼B226
* **参赛设备**：机房电脑
* **题目数量**：8题左右，题目按随机顺序排列（A 题不一定最简单，需通过榜单和题面自行判断）
* **计分与排名规则（XCPC 赛制）**：
	1. **通过题数优先**：解决题目数量（AC 数）多者排名靠前。
	2. **罚时次之**：AC 数相同时，总罚时少者排名靠前。
	3. **罚时计算**：每道通过题目的罚时 = 从比赛开始到首次通过该题的分钟数 + 该题此前每次未通过提交× 20 分钟。未通过的题目不计入罚时。
* **允许携带物品**：任意数量纸质资料（算法书籍、打印的个人代码模板、字典等）、文具。严禁携带任何电子存储设备、手机（需关机或静音集中存放）、智能手表及未经允许的联网设备。

## 评测结果速查与排查

| 状态缩写 | 全称                   | 常见原因与排查方向 |
| ------- | --------------------- | --------------- |
| **AC**  | Accepted              | 答案正确。 |
| **WA**  | Wrong Answer          | 逻辑漏洞、边界条件、数据范围溢出、多组数据未清空数组/变量。 |
| **TLE** | Time Limit Exceeded   | 算法时间复杂度过高、死循环、cin/cout 未关闭同步流且数据量极大、使用了过多的 endl |
| **MLE** | Memory Limit Exceeded | 全局数组开得过大、递归过深导致栈溢出、容器无限插入元素。|
| **RE**  | Runtime Error         | 数组越界（最常见）、除以零或对零取模、空指针解引用、递归爆栈。|
| **CE**  | Compilation Error     | 语法错误、选错提交语言或语言版本 |

遇到错误时，建议先阅读编译信息或检查程序逻辑，不要盲目重复提交。

## 比赛纪律

**独立完成，诚信参赛。**

本次比赛考察参赛者真实的独立编程能力。比赛期间严禁使用 AI 辅助完成题目。

### 允许的行为

- 使用本地 IDE 编写代码。
- 使用本地编译器编译程序。
- 使用本地调试工具排查程序错误。
- 查阅本地语言标准库文档及自带的纸质材料。

### 禁止的行为

- 使用 ChatGPT、DeepSeek、Claude 等 AI 工具获取解题思路或代码。
- 使用 GitHub Copilot、Cursor 等 AI 编程辅助功能。
- 使用浏览器 AI 插件或其他 AI 代理辅助解题。
- 与其他参赛者交流题目思路或代码。
- 复制、传播其他参赛者的程序。
- 委托他人代写或通过远程控制等方式获取帮助。

**特别提醒：** 不要认为只要没有直接复制 AI 生成的代码就不算违规。利用 AI 获取思路、分析错误或优化代码，同样属于违规辅助。

违反比赛纪律的，组织方有权根据情节取消成绩、取消评奖资格或采取其他处理措施。

## 比赛建议

### 1. 合理安排时间

* 开始时先浏览所有题目，了解整体难度。
* 优先选择自己有把握的题目。
* 先完成基础题，再尝试提高题。
* 遇到暂时无法解决的问题，可以先跳过。
* 不要在一道题目上投入过多时间而忽略其他机会。

### 2. 重视细节

* 输入输出格式错误。
* 数组下标越界。
* 循环边界错误。
* 整数溢出。
* 特殊数据没有考虑。
* 输出多余空格或调试信息。
* 未正确处理多组测试数据。
* 是否存在整数溢出或其他运行时错误。

### 3. 保持良好心态

第一次参加比赛时，可能会遇到读不懂题目、思路不清晰或者代码无法通过的情况。

这些都是学习过程中的正常现象。

不要过分关注排名，也不要因为没有通过某道题而失去信心。认真完成每一道自己能够解决的题目，就是一次有价值的训练。

## 赛后安排

比赛结束并不意味着学习结束。

建议大家：

1. 查看自己的比赛成绩和题目通过情况。
2. 整理比赛中遇到的问题。
3. 复盘没有解决的题目，分析原因。
4. 补充自己尚未掌握的知识点。
5. 尝试独立完成比赛题目的补题。

对于暂时没有通过的题目，可以先独立思考，再查阅资料或参加赛后讲解。
